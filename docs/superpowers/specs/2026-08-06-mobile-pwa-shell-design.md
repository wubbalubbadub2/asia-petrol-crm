# Мобильное приложение: оболочка PWA и мобильные представления

Дата: 2026-08-06
Статус: утверждено к реализации
Спека 1 из 2. Следующая — «Чат сделки: вкладка, непрочитанное, push».

## Задача

Обеспечить работу ключевых функций системы с телефона — в офисе, в дороге и на складе.
Установка на домашний экран, без публикации в App Store и Google Play.

## Что выяснилось при разборе

Исходно обсуждался Capacitor и установка файлом-дистрибутивом. Разбор показал, что это
не тот инструмент:

- **iOS не даёт раздавать файл.** Enterprise-программа требует юрлицо и штат от 100
  человек, Ad Hoc ограничен сотней устройств с ручной регистрацией каждого, TestFlight
  живёт 90 дней на сборку. Обойти подпись Apple нельзя ни в одном варианте.
- **Capacitor требует статической сборки**, а Next.js App Router с динамическим
  маршрутом `/deals/[id]` так не собирается без переделки маршрутизации.
- **PWA снимает обе проблемы разом**: приложение остаётся обычным развёрнутым Next.js,
  ставится с домашнего экрана на обеих платформах, обновляется мгновенно.

Capacitor остаётся запасным вариантом на будущее — если офлайн-ввод на складе упрётся
в ограничения хранилища iOS. Код PWA при этом переиспользуется целиком.

Кодовая база к этому готова: 24 из 35 страниц уже клиентские, данные идут напрямую
в Supabase под RLS, кастомного middleware нет, мобильный выдвижной сайдбар (`Sheet`)
в макете уже присутствует.

## Принятые решения (владелец, 2026-08-06)

1. Доставка — **PWA**, не Capacitor.
2. Офлайн — **только чтение из кэша**; любая правка требует сети и честно об этом говорит.
3. Паспорт сделок на телефоне — **карточки**, переход в существующую карточку сделки.
4. Навигация — **нижние вкладки**, первая вкладка «Главная» со сводкой.
5. Чат — **отдельная вкладка + непрочитанное + push**, выносится в спеку 2.
6. Лента сделки — **единый поток** (люди и системные события вместе) с фильтрами-чипами.
7. Работа делится на **две спеки, выпускаемые подряд**.

## Границы

**В спеке:** манифест и иконки, метатеги окна, сервис-воркер, сохранение кэша между
запусками, поведение без сети, нижняя навигация, мобильные виды «Главная», «Сделки»,
«Реестр», «ДТ-КТ», ревизия карточки сделки на узком экране.

**Вне спеки:** чат, отметки прочтения, push (спека 2); разделы «Просрочки», «Календарь»,
«Логистика»; согласование сделок и трейдерский модуль с ограничениями по конфиденциальным
полям; офлайн-ввод с очередью; Capacitor.

## 1. Оболочка PWA

### 1.1 Манифест и иконки

`src/app/manifest.ts` — Next отдаёт манифест как маршрут, отдельный файл в `public/`
не нужен.

| Поле | Значение |
|---|---|
| `name` | Singularity Trading CRM |
| `short_name` | Singularity |
| `display` | `standalone` |
| `start_url` | `/` |
| `theme_color` | `#f59e0b` (янтарный акцент интерфейса) |
| `background_color` | `#fafaf9` (фон приложения) |
| `lang` | `ru` |
| `orientation` | не задаём — планшет должен уметь альбомную |

Иконок в проекте нет: в `public/` лежат только `file.svg`, `globe.svg`, `next.svg`,
`vercel.svg`, `window.svg` от `create-next-app`. Фирменный знак существует только как
разметка — иконка `Fuel` из `lucide-react` на янтарном градиенте
(`src/components/layout/sidebar.tsx:176`).

Из этого же знака генерируются файлы: `icon-192.png`, `icon-512.png`,
`icon-maskable-512.png` (с безопасными полями под обрезку в круг) и `apple-touch-icon.png`
(180×180). Внешний дизайн не привлекается — вид остаётся прежним.

### 1.2 Метатеги окна

В `src/app/layout.tsx` есть `metadata`, но нет `viewport`. Добавляется экспорт `viewport`
с `themeColor: "#f59e0b"` и `viewportFit: "cover"` — без последнего на телефонах с вырезом
интерфейс уезжает под чёлку.

### 1.3 Сервис-воркер

Пишем свой в `public/sw.js`, без библиотек. Задача узкая, и `next-pwa` тянул бы
зависимость и build-шаг ради трёх правил:

| Что | Стратегия | Почему |
|---|---|---|
| `/_next/static/*` | сначала кэш | Имена содержат хеш, содержимое неизменно |
| Страницы (навигация) | сначала сеть, при отказе кэш | Свежесть важнее, но офлайн должен открыться |
| Запросы к Supabase | не перехватываем | Данные кэшируются слоем приложения (см. 1.4), а не воркером |

Регистрация — в клиентском компоненте, монтируемом из корневого макета.
Обновление воркера: при появлении новой версии показываем ненавязчивую плашку
«Доступно обновление — перезагрузить», без принудительной перезагрузки посреди работы.

### 1.4 Сохранение кэша между запусками

В приложении уже есть слой кэширования с TTL: `dealsCache` и `dealByIdCache`
(`use-deals.ts`), `appsCache` (`use-applications.ts`), кэши строк вариантов
(`use-deal-lines.ts`), справочники (`refs.ts`). Все они живут в памяти модуля и исчезают
при перезагрузке страницы.

Добавляется тонкий адаптер поверх них: при записи в кэш значение асинхронно зеркалится
в IndexedDB, при старте приложения кэши гидратируются обратно. Существующая логика
не переписывается — меняются только точки записи и добавляется гидратация.

Вместе с данными сохраняется отметка времени получения. В шапке мобильного приложения
она показывается как «данные от 14:32», когда сети нет.

**Что кэшируем:** список сделок текущего года, открытые карточки сделок, справочники,
реестр по открытым сделкам. Отчёты и выгрузки — нет: они требуют свежих курсов и
пересчёта, показывать их из кэша опаснее, чем не показывать вовсе.

### 1.5 Безопасность кэша

В IndexedDB окажутся финансовые данные, отфильтрованные RLS под конкретного
пользователя. Телефон могут передать другому сотруднику.

**Требование:** выход из системы полностью очищает IndexedDB, кэши сервис-воркера
с данными и сохранённые рабочие вкладки (`asia-petrol-tabs-v1` — в них лежат коды
и идентификаторы сделок). Кэш статики (`/_next/static/*`) остаётся: он одинаков
для всех и данных не содержит.

Это же срабатывает при смене пользователя: если после входа идентификатор пользователя
не совпал с тем, чьи данные лежат в хранилище, хранилище очищается до загрузки.

### 1.6 Поведение без сети при входе

Сейчас `AuthGuard` при недействительной сессии отправляет на `/login`. Без сети
обновить токен нельзя — пользователь вместо кэша увидит форму входа, и офлайн-режим
не заработает вовсе.

**Правило:** нет сети + в хранилище есть сеанс, у которого не истёк срок → пускаем
в приложение в режиме чтения, с явной плашкой «Нет сети. Данные от 14:32. Изменения
недоступны». Все элементы ввода в этом режиме заблокированы.

Если срок сеанса истёк — на форму входа, как сейчас: показывать финансовые данные
по просроченному сеансу нельзя.

## 2. Навигация

### 2.1 Порог переключения

Мобильный режим включается **уже 768 пикселей** (`< md`). Шире — текущее поведение
без изменений, включая планшеты: в альбомной ориентации существующая таблица
с горизонтальной прокруткой читается нормально, а третья раскладка — лишняя работа
и лишняя поверхность для ошибок.

Существующий выдвижной сайдбар (`Sheet`, `layout.tsx:117`) на телефоне не используется —
его заменяют вкладки. На планшете он остаётся как сейчас.

### 2.2 Вкладки

Четыре в этой спеке: **Главная · Сделки · Реестр · Ещё**.

«Ещё» содержит ДТ-КТ, справочники, настройки, выход. Пятая вкладка «Чаты» вставляется
второй спекой между «Сделки» и «Реестр»; сейчас место под неё заложено в компоновке,
но пустая вкладка не рисуется.

Панель вкладок фиксирована внизу, с отступом под системную полосу жестов
(`env(safe-area-inset-bottom)`).

## 3. Мобильные представления

### 3.1 Главная

Плитки со сводкой по загруженному году, считаются из уже загруженного списка сделок —
дополнительных запросов нет:

- баланс поставщикам (сумма `supplier_balance`);
- долг покупателей (сумма `buyer_debt`);
- число сделок в году.

Ниже — открытые сделки: система рабочих вкладок уже сохраняет их в `localStorage`
под ключом `asia-petrol-tabs-v1` (`src/lib/contexts/tabs-context.tsx`), и на телефоне
этот же список показывается как «продолжить работу».

Отдельных «быстрых действий» в этой версии нет намеренно: пока в системе нет действия,
которое осмысленно делать в один тап с главного экрана, кнопка ради кнопки не нужна.
Они появятся вместе с чатом и согласованием.

### 3.2 Сделки

Список карточек вместо таблицы. Содержимое карточки:

```
KG/26/373                    [KG]
июнь 2026 · Мазут · ПКОП
Поставщик      Afiyat Energy
Покупатель     Quantum Energy
Оплата            143 000,00 $
Возврат/Перезачет   9 020,00 $
Баланс                 0,00 $
```

Тап открывает существующую карточку сделки.

Поиск выносится наверх и всегда виден — при 530 сделках он важнее фильтров.
Фильтры (год, поставщик, покупатель, ГСМ, месяц и прочие) убираются в выдвижную панель
со счётчиком активных. Вся логика фильтрации переиспользуется как есть: она уже
клиентская и работает поверх кэша года.

Список виртуализуется — иначе 530 карточек уронят прокрутку на телефоне.

### 3.3 Карточка сделки

Секции и сворачивание уже есть и на узком экране работают. Ревизии требует то, что
внутри секций: редактор строк-вариантов, блок оплат, цены по отгрузкам — это таблицы.

Это самая непредсказуемая по трудозатратам часть спеки. Принимается только по живому
экрану: каждая секция открывается на телефоне и проверяется на переполнение по ширине,
попадание пальцем и читаемость. Отдельный шаг плана с проверкой в браузере.

### 3.4 Реестр

Реестр уже сгруппирован по сделкам. На телефоне — карточка на сделку, внутри строки
вагонов: номер, объём, дата. Массовое добавление и импорт на телефоне не показываются:
это работа за компьютером.

### 3.5 ДТ-КТ

Строка на экспедитора и группу компаний превращается в карточку: контрагент, год,
входящее сальдо, оплата, реестр, исходящее сальдо. Только чтение — правка расчётов
с телефона в эту версию не входит.

## 4. Проверка

Мобильную вёрстку нельзя принимать по коду — только по реальному экрану.

1. `npm run verify` и существующий набор тестов.
2. Playwright в мобильном окне (390×844) по путям: вход → список сделок → открытие
   сделки → реестр. Требует `E2E_EMAIL` / `E2E_PASSWORD`, как существующий smoke-тест.
3. Устанавливаемость: приложение предлагает установку, ставится на домашний экран.
   Проверяется отдельно на Android и на iPhone через Safari — поведение платформ
   различается, обещать одинаковое нельзя.
4. Офлайн-старт: включить режим полёта, открыть приложение с домашнего экрана,
   убедиться, что видны данные, показана метка времени и заблокирован ввод.
5. Очистка при выходе: выйти, снова открыть — убедиться, что данных в хранилище нет.
6. Запись в `CHANGELOG-SINCE-EXTRACTION.md`.

## 5. Открытые вопросы для следующих проектов

Зафиксированы здесь, чтобы не потерялись; в этой спеке не решаются.

- **Конфиденциальные поля и чат.** Доступ к обсуждению сделки определяется доступом
  к сделке. Но в требованиях есть ограничение видимости отдельных полей для трейдеров.
  Возможна ситуация: человек видит переписку, где коллеги называют цифры, которые сам
  он в карточке видеть не должен. Решается в проекте согласования (проект 6).
- **Push на iOS** работают только с версии 16.4 и только для приложения, добавленного
  на домашний экран. Перед спекой 2 нужно знать, какие телефоны у сотрудников.
- **Обсуждения не про конкретную сделку** (про контрагента, про день) в модели
  «ветка = сделка» места не имеют и останутся в мессенджере. Оценить после запуска чата.
